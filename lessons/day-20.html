The big idea

This lesson assembles the Month-End Planning workflow from earlier components. The sequence updates Current Month, loads Actuals, calculates Revenue, pushes to Reporting and returns a summary. Reuse the tested client, approval and monitoring helpers instead of rebuilding their REST logic. Every dependent step needs evidence that its prerequisite completed successfully.

Open audio file

Follow the workflow

In the successful fixture, the approved variable update is verified by reading it back. The Actuals integration is submitted and monitored. The calculation then runs and is verified before the Reporting push. A helper must respect each operation's result contract: an immediate variable update does not need an invented asynchronous job identifier. In the failed-load case, calculation and reporting are skipped. The earlier variable change is still recorded; a later failure does not automatically roll it back.

Open audio file

If you are stuck

If you are stuck, write the business sequence first and identify the evidence required after each operation. Connect one existing helper at a time. Use fake adapters to test success and a failed integration before any authorized tenant run. Preserve the exact point of view throughout the chain. The final summary should show what changed, what failed and what was skipped, rather than presenting the whole workflow as an all-or-nothing transaction.

day-20-example.py · Python
MONTH_END_STEPS = [
    "update_CurrentMonth", "load_Actuals", "calculate_Revenue", "push_To_Reporting"
]

def run_month_end(operations, scenario, period, year):
    results = []
    for step in MONTH_END_STEPS:
        result = operations[step](scenario=scenario, period=period, year=year)
        result = operations["wait_for_terminal_status"](result)
        results.append({"step": step, "result": result})
        if result["status"] != "SUCCESS":
            break
    return results  # Use prebuilt helper functions from previous days.
Explain this code
run_month_end reuses operation adapters. Each adapter must provide verified completion: read-back for an immediate variable update and terminal job monitoring where applicable. Stop dependents on an unsuccessful or unknown outcome.
