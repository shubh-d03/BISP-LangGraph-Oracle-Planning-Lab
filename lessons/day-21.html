The big idea

Reliability comes from checks around the model's proposal. Validate the operation, rule and members against approved application data. Check the user's access separately. Present the exact proposed write for approval where required. A request can pass one check and still fail another. Forecast seeding is a useful example because it can overwrite existing forecast values.

Open audio file

Follow the workflow

Inspect the approved training request for Forecast Seeding in September. Its metadata and permission checks pass, and explicit approval permits one mock action. Now choose an invalid Scenario. That request must stop before execution and name the value needing correction. Finally inspect denial: valid metadata does not override a rejected proposal. The static lists in the Python sample are classroom fixtures. A live assistant needs approved current metadata for the real application.

Open audio file

If you are stuck

If you are stuck, do not combine all guardrails into one vague yes-or-no result. Record which inputs were valid, whether the user was authorized, and which exact proposal was approved. Test each rejected boundary with a call counter. Revised parameters must be checked and reviewed again. A useful correction explains what the user needs to provide or change without exposing secret information or relying on the model's confidence.

day-21-example.py · Python
APPROVED_RULES = {"Forecast_Seeding"}
VALID_SCENARIOS = {"Forecast", "Plan", "Budget"}
VALID_PERIODS = {"Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"}

def validate_forecast(request):
    return (request.get("rule") in APPROVED_RULES
            and request.get("scenario") in VALID_SCENARIOS
            and request.get("period") in VALID_PERIODS)

# This static sample list is for a LAB only; live agents must check metadata.
Explain this code
validate_forecast illustrates allowlist checks using static lab data. It does not establish authorization or approval, and production metadata must come from approved application data.
