The big idea

Dynamic workflow decisions depend on evidence. A dependent calculation may continue only when its required load has confirmed success. Running, failed and unknown are different outcomes, but none permits that dependent calculation yet. The summary must preserve these distinctions instead of declaring success merely because no failure was recorded.

Open audio file

Follow the workflow

Select each load-status case. Confirmed success chooses the calculation route. Failure chooses a stop and records calculation as skipped. A running load remains pending. A timeout leaves the outcome unknown. The summary should include job identifiers and meaningful messages for completed, failed and skipped work. In the corrected code example, full success is checked explicitly. Empty or incomplete evidence cannot become a successful overall result.

If you are stuck

If you are stuck, test more than success and failure. Add running, unknown timeout, an empty result list and a skipped-only list. Ask whether your summary accidentally treats any of these as complete. Avoid a simple rule that says, if nothing failed, everything succeeded. Instead establish that every required step actually succeeded. Show skipped operations and their reasons so the user can understand what was not executed.

def next_step(state):
    return "calculate" if state.get("load_status") == "SUCCESS" else "stop"

# Map calculate to the calculation node; map stop to the summary node.

def summarize(steps):
    statuses = [step.get("status", "UNKNOWN") for step in steps]
    if "FAILED" in statuses:
        overall = "FAILED"
    elif any(str(value).startswith("UNKNOWN") for value in statuses):
        overall = "UNKNOWN"
    elif any(value in {"RUNNING", "SUBMITTED", "PENDING"} for value in statuses):
        overall = "PENDING"
    elif statuses and all(value == "SUCCESS" for value in statuses):
        overall = "SUCCESS"
    else:
        overall = "UNKNOWN"  # Empty or skipped/incomplete evidence.
    return {"steps": steps, "overall": overall}
Explain this code
The routing function continues only on load_status == SUCCESS. The summary example has been corrected in this rollout so unfinished or skipped outcomes cannot be mistaken for a complete success.
