The big idea

LangGraph helps describe an application as a graph of connected steps. A node is one step, such as validating a request. An edge decides which step comes next. State is the shared collection of values carried through the workflow. In Planning, that state might hold a rule name, Scenario, Period and a returned job identifier. This lesson is about following those values through a workflow, rather than memorizing framework terminology.

Open audio file

Follow the workflow

Follow the valid request in the graph explorer. The request enters shared state. Validation checks whether the required members are present. A conditional edge chooses the rule tool when validation passes. The mock tool adds a job identifier, and the result is returned for monitoring. Now switch to the missing-period case. Validation should choose clarification instead. The rule tool is skipped. That branch demonstrates why choosing the next node is a business decision, not just a line drawn between boxes.

Open audio file

If you are stuck

If the graph feels confusing, select one node at a time and read the state inspector beside it. Ask what values were already present and what this node added. A node does not have to replace the entire state. It can return just an update. Do not treat a submitted job as a completed calculation. In this example, the final result still needs monitoring. Once you can explain why the missing Period prevents submission, you have understood the main idea.

02 / UNDERSTAND THE CONCEPT

A workflow you can reason about

01Graph

A graph models a workflow as connected steps called nodes. Think of it as the map of your Planning automation.

02State

State holds the information shared across steps, such as the requested rule, parameters and job result.

03Edges

Edges determine the next step; conditional edges choose a branch using known state.

04Controlled execution

A typical EPM graph validates inputs before it allows a REST tool to run. Missing members should route to clarification.

Oracle Planning context. A consultant requests Revenue_Calculation_RTP for Forecast / Sep / FY26. The graph carries those parameters through validation, tool execution and a structured result.
