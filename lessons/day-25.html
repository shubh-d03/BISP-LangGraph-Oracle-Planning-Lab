The big idea

The final lesson turns the course into a demonstration with evidence. Cover the valid Business Rule flow and the Month-End workflow, together with missing values, invalid members, denied approvals, job failure and follow-ups. Distinguish what your implementation has actually passed from what was only shown in a browser fixture or planned for later production hardening.

Open audio file

Follow the workflow

Explore the six acceptance scenarios. Each shows expected behavior and the evidence you should collect from your own assistant. A complete approved request needs submission and terminal-result evidence. An incomplete or invalid request needs a correction and no write. Denial must cancel execution. A failed prerequisite must skip dependents. A follow-up changes the named field and requests fresh approval. These browser examples explain the expected behavior; they do not certify your Python implementation.

Open audio file

If you are stuck

If you are stuck preparing the final demo, make a short evidence checklist for each scenario. Run it against your actual assembled assistant with controlled mocks, and add authorized tenant evidence only where available. A printed list of expected outcomes is not a test: compare actual routes, state and tool-call counts with assertions. State clearly which parts were mocked. Demonstrate one controlled failure as well as a happy path, then explain which course components were reused.
