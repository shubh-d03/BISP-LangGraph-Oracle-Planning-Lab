The big idea

Data Integration automation runs a configured integration, rather than a Business Rule calculation. That integration has its own supported request contract, inputs and permissions. Validate the integration name before submission and keep the returned run identifier. Even after a successful job, the business result may still require reconciliation of loaded data and totals. This lesson separates those responsibilities.

Open audio file

Follow the workflow

Follow the configured training integration through collection, validation, submission and monitoring handoff. Its period must come from the approved training configuration. The dedicated client method owns the exact endpoint, job type and parameter encoding. Compare the valid case with a blank or unlisted integration name. Those requests should stop before submission. After a real authorized run, inspect terminal status and verify the imported data rather than relying only on a friendly success message.

Open audio file

If you are stuck

If you are stuck, use the smallest mock first. Supply one allowed integration name and its required parameter dictionary, then check the client call. Next try an empty name and an unsupported name while counting submission calls. Both should leave the count at zero and return a useful correction. Do not copy a rule payload into an integration method just because both operations are jobs. Preserve the integration's own verified contract.

day-09-example.py · Python
def run_data_integration(client, integration_name: str, params: dict):
    if not integration_name.strip():
        raise ValueError("Integration name is required")
    if integration_name not in client.allowed_integrations:
        raise ValueError("Integration is not configured or allowed")
    # Exact endpoint, job type and parameters must be verified.
    return client.submit_verified_integration(integration_name, params)
Explain this code
run_data_integration validates its name against the configured allowlist. The dedicated client method owns endpoint details. Preserve submission evidence, then use monitoring and data checks as separate steps.
