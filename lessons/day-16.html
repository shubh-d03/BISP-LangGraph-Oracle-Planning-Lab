The big idea

Human approval creates a pause between proposing a sensitive action and executing it. The graph saves a checkpoint and waits for an explicit decision. A complete, valid proposal can still be rejected. This lesson demonstrates approval, rejection and revised parameters using a mocked variable update. No Oracle connection is made by the simulation.

Open audio file

Follow the workflow

The assistant proposes changing Current Month from August to September in the training application. Review the operation, environment and exact proposed value. Approve follows the revalidation branch and permits one mock write. Reject ends without a write. Now change the proposed value: any earlier approval is cleared and a fresh review is needed. An invalid member must still fail validation after an approval decision. Approval does not replace input validation or authorization.

If you are stuck

If you are stuck implementing the Python exercise, inspect three boundaries separately. First, the graph must pause before the write tool. Second, it must resume the correct checkpoint using the same thread configuration. Third, rejection must route to an end without calling the write function. Use a call counter to verify this behavior. Test a revised value as a new proposal. If a previous approval still applies after editing the parameters, your guard is incomplete.

02 / UNDERSTAND THE CONCEPT

Keep the human in control

01Proposal ≠ permission

A proposed action is not an approved action. Show the exact operation, environment and parameters for review.

02Pause with a checkpoint

An interrupt can pause a graph and resume from a saved checkpoint.

03Approval is explicit

Only a positive decision for the current proposed action may reach the write branch.

04Recheck changed inputs

Revalidate modified inputs and authorization before running. Changes require a fresh review.

Oracle Planning context. Preview an update to CurrentMonth from Aug to Sep in the training application. Approval resumes the checked action; rejection ends with no write.

day-16-example.py · Python
from langgraph.types import interrupt, Command

def approval_node(state):
    decision = interrupt({"action": state["operation"],
                          "parameters": state["parameters"]})
    return {"approved": decision.get("approved") is True}

# Compile with a checkpointer.
# app.invoke(initial_state, config=config)  # pauses
# app.invoke(Command(resume={"approved": False}), config=config)
# Route approved=False to END without calling a write tool.
Explain this code
interrupt() presents the proposal and saves a pause point when the graph uses a checkpointer. Resume with the same thread config. Route approved=False to END; revalidate approval and parameters before a write.

Common mistakes
Writing before approval
The interrupted graph must not call a write tool until the current action is approved and checked.
Reusing approval after an edit
A revised parameter creates a revised proposal. Validate it and ask for approval again.
