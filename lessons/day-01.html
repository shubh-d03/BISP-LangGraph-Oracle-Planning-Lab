The big idea

This lesson introduces an AI agent for Oracle EPM Planning. Start with a familiar task: a consultant wants to run a revenue calculation. A traditional script follows instructions and expects its inputs in a fixed format. An agent can interpret a request in ordinary language and ask for missing details. The important distinction is that the language model proposes an action. A tested tool, with validation and permission checks, performs the allowed operation.

Follow the workflow

Imagine the request, run the revenue calculation for Forecast in September. First identify the operation: this is a Business Rule calculation. Next collect the exact deployed rule name, Scenario, Period and Year. Validate those values against the application. If a change requires approval, show the proposal before running it. Finally, inspect the job result. The browser example is a simulation of these decisions; it does not connect to Oracle. A useful assistant explains what it knows, what is missing, and what actually happened.

If you are stuck

If you are stuck, separate the request into three questions. What operation does the user want? What information does that operation need? What evidence is required before it can run? Try an incomplete request such as, run the calculation. The correct next action is to clarify the rule and Planning point of view, not to guess. You do not need to write Python today. Explain the difference between interpreting a request and executing a tool, then explore both sample cases.

02 / CLASS NOTES

Core concepts

Fixed instructions

A script follows a fixed set of instructions; an agent interprets a request and chooses from approved actions.

Language interpretation

An LLM interprets language but does not itself execute a Planning job. Tools connect the model to tested Python functions.

Controlled tools

An EPM agent should identify an operation, collect parameters, validate access and request approval before making changes.

Planning use cases

Examples include launching calculations, preparing forecast runs and summarizing job results.

Oracle Planning context. A Planning consultant wants to run Revenue_Calculation for Forecast / Sep / FY26. An incomplete request needs a clarification before it can become an execution proposal.
