The big idea

Capability integration registers existing operations with the final assistant. Rules, integrations, pipelines, substitution variables, job status and Month-End each keep their own schemas and permissions. Sharing an EPM client does not make these operations interchangeable. The tool registry must contain actual tested callables, not just a list of string names.

Open audio file

Follow the workflow

Inspect a registered Business Rule capability. Its schema describes the rule and configured runtime prompts, while the shared client performs the verified request. Then inspect the Month-End capability. It wraps the existing workflow and preserves its ordered step evidence instead of rebuilding its REST calls. An arbitrary model-supplied function name must be rejected if it is not registered. Registration and selection are controlled boundaries, not blanket authorization to execute.

Open audio file

If you are stuck

If you are stuck, inspect the value stored for each registry entry. Can it actually be called with the documented inputs? Does it return the normalized result expected by the graph? Keep operation-specific validation attached to the execution boundary. Start with preview inputs before an authorized sandbox run. The composite Month-End tool should call the reused workflow once and return its results, including failure and skipped-step evidence.
