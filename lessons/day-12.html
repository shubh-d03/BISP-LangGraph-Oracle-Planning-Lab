The big idea

Today you connect a tested Python capability to LangGraph through a tool boundary. A tool has an explicit input schema and a description of what it can do. The API client remains separate from model decisions. The demonstration is intentionally a preview tool, so you can test its invocation and result shape without submitting an Oracle job.

Open audio file

Follow the workflow

The graph receives the rule name and passes it to the preview tool. The tool returns a normalized dictionary describing the operation, rule and preview-only status. A response node reads that dictionary and explains the proposal. In the invalid-input case, a blank rule name must be caught before an execution tool is allowed to run. Later, an authorized execution implementation can reuse the verified client, while keeping the same controlled boundary.

Open audio file

If you are stuck

If you are stuck, test the wrapper before testing the graph. Does it accept the named argument you expect? Does its description accurately say preview or execution? Does the returned status match that promise? Then connect a graph node that invokes the wrapper and stores its result in a declared state field. Do not duplicate the tool logic inside the node or return unfiltered exceptions that could expose credentials.

day-12-example.py · Python
from langchain_core.tools import tool

@tool
def preview_business_rule(rule_name: str) -> dict:
    """Preview a configured Oracle Planning Business Rule. No live execution."""
    return {"operation": "business_rule", "rule": rule_name,
            "status": "preview_only"}

print(preview_business_rule.invoke({"rule_name": "Revenue_Calculation"}))
Explain this code
The @tool wrapper exposes a typed argument and a clear description. The supplied implementation returns preview_only. Add validation before connecting a real execution method, and use a response node to explain the structured result.
