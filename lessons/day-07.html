The big idea

REST APIs provide a structured way for Python to communicate with Oracle EPM over HTTPS. A request has a method, a verified endpoint and sometimes a payload. The response has an HTTP status and may contain structured data. Begin with a read-only request so you can inspect this boundary without changing Planning data. Keep authentication and common error handling in a reusable client or helper.

Open audio file

Follow the workflow

The successful lesson fixture represents a read-only application-information request. Inspect the method, then the HTTP outcome, then a known response field. In your Python environment, use the endpoint and field names verified for your own tenant. An unauthorized response must be handled as an error before treating it as normal data. A timeout is different again: it means the request outcome was not confirmed. For an asynchronous write, HTTP acceptance is not evidence that its job finished.

Open audio file

If you are stuck

If you are stuck, check one boundary at a time. Is the base URL configured? Is the path a verified read-only endpoint? Is supported authentication configured without being printed? Does the helper set a timeout and check HTTP errors before parsing JSON? Use a fake session to test error handling. Never test a retry strategy by repeatedly submitting a real write, because a timed-out request may already have reached Oracle.

02 / CLASS NOTES

Core concepts

HTTPS and endpoints

Oracle EPM REST operations use an HTTPS base URL and operation-specific endpoints.

Authentication

Use supported authentication for the environment; never print or commit secrets.

HTTP vs job status

HTTP success means a request was accepted, not necessarily that an asynchronous job completed.

A shared request helper

Centralizing headers, timeouts and error handling avoids repeated fragile code.

Oracle Planning context. Inspect a known application field using a verified, read-only tenant endpoint, then centralize timeouts and response handling.

04 / INSTRUCTOR WALKTHROUGH
Guided demonstration
INSTRUCTOR WALKTHROUGH · DISCUSS EACH STEP
Start with a pre-verified Planning endpoint for the training tenant.
day-07-example.py · Python
import os, requests
from requests.auth import HTTPBasicAuth

BASE_URL = os.environ["EPM_BASE_URL"].rstrip("/")
USER = os.environ["EPM_USER"]
PASSWORD = os.environ["EPM_PASSWORD"]

session = requests.Session()
session.auth = HTTPBasicAuth(USER, PASSWORD)

def request_epm(method: str, verified_path: str, payload=None):
    response = session.request(method, BASE_URL + verified_path,
                               json=payload, timeout=30)
    response.raise_for_status()
    return response.json() if response.content else {}

# Use a verified READ-ONLY Oracle endpoint for your tenant:
# print(request_epm("GET", os.environ["EPM_INFO_PATH"]))
Explain this code
The session owns authentication. request_epm sets a timeout, checks HTTP errors and parses the response. Its verified_path must come from current tenant documentation; the browser fixture does not certify a real endpoint.
